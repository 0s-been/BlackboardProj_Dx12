## 2. 테스트 환경과 방법

| 항목 | 내용 |
|---|---|
| 빌드 | MinGW-w64 GCC 13 크로스 컴파일 (Release `-O2`, Debug `-O0 -D_DEBUG`) |
| 실행 | Wine 9.0 + vkd3d(Direct3D 12 → Vulkan 변환) + llvmpipe(CPU 소프트웨어 Vulkan), Xvfb 가상 화면 |
| 조작 | `xdotool`로 마우스 이동·클릭·드래그·휠, 창 크기 변경 |
| 판정 | 화면 캡처의 픽셀 색과 선 굵기(픽셀 수)를 기대값과 비교 |
| 한글 글꼴 | Wine에는 맑은 고딕이 없어서 나눔고딕을 `malgun.ttf` 이름으로 넣고 테스트 |

**한계**: 실제 Windows와 실제 GPU가 아니라 호환 계층에서 실행했습니다. D3D12 디버그 레이어는 Wine에서 지원되지 않아 Vulkan 검증 레이어로 대신했습니다. 그래서 7장의 항목은 Windows PC에서 한 번 더 확인해야 합니다.

### 테스트 실행 방법

- **단위 테스트 (Windows)**: `BlackboardProj.sln` → `UnitTests` 프로젝트를 시작 프로젝트로 설정하고 실행합니다. 실패하면 종료 코드가 1입니다.
- **E2E (Linux + Wine)**: `python3 Tests/E2E/e2e_wine.py <BlackboardProj.exe> <결과폴더>`. 결과 폴더에 단계별 화면 캡처와 `e2e_results.txt`가 남습니다.

## 5. 테스트 쪽 문제 (프로그램 결함 아님)

- **U14 첫 실행 실패**: Wine이 C 로케일로 실행돼 한글 파일 이름을 만들 수 없었습니다. `_wfopen`으로 직접 열어도 똑같이 실패해서 환경 문제로 판단했고, UTF-8 로케일로 실행하자 통과했습니다.
- **TC20 1차 실패**: 저장 파일은 정상적으로 만들어졌지만, Wine 파일 대화상자가 느려서 테스트가 파일이 생기기 전에 확인했습니다. 최대 15초까지 기다리도록 테스트를 고쳤습니다.

## 6. 디버깅 지점

문제가 생겼을 때 중단점을 걸거나 값을 확인할 위치입니다. 줄 번호는 현재 코드 기준입니다.

### 6.1 공통 도구

- **D3D12 디버그 레이어**: Debug 빌드에서 자동으로 켜집니다(`Dx12Core.cpp:15`). 잘못된 API 사용은 Visual Studio **출력** 창에 `D3D12 ERROR`로 나옵니다. 가장 먼저 확인할 곳입니다.
- **PIX for Windows / VS 그래픽 디버거**: 한 프레임을 캡처해 정점 버퍼 내용, 루트 상수 값, 파이프라인 상태, 백버퍼를 단계별로 볼 수 있습니다. "선이 안 보인다"류의 문제에 유용합니다.
- **OutputDebugString 로그**: 셰이더 컴파일 오류, 장치 제거 원인, 글꼴 대체가 출력 창에 남습니다.

### 6.2 DirectX 12 Core (`Core/Dx12Core.cpp`)

| 위치 | 확인할 것 | 관련 증상 |
|---|---|---|

## 7. Windows 실기에서 추가로 확인할 항목

이 환경에서 확인할 수 없어 남은 항목입니다.

1. Debug 빌드 실행 중 출력 창에 `D3D12 ERROR` / `WARNING`이 없는지
2. 실제 맑은 고딕으로 UI 글자가 잘리지 않는지 (나눔고딕보다 글자 폭이 약간 넓음)
3. 디스플레이 배율 125%/150%에서 화면이 흐리지 않은지 (현재 DPI 대응 없음)
4. 창 테두리를 끌어 크기를 바꾸는 동안의 화면 (끄는 동안은 갱신이 멈추고 놓으면 정상인 것이 현재 설계)
5. 터치패드 두 손가락 스크롤로 굵기 조절 (1칸보다 작은 휠 값 누적)
6. 실제 GPU에서 선 수천 개를 그렸을 때 프레임 유지
